# Git vs SVN: ответы на вопросы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто **указатель на коммит** (файл размером 41 байт,
содержащий SHA-1 хеш). Создание ветки не копирует файлы, а лишь
записывает ссылку. Переключение между ветками — это смена указателя
HEAD и обновление рабочей директории, что происходит мгновенно.

В SVN ветка — это **физическая копия директории** внутри репозитория
(по соглашению `branches/имя-ветки`). Сервер вынужден хранить полную
копию дерева, а переключение требует скачивания файлов с сервера.
Поэтому ветвление в SVN медленное и «дорогое» по ресурсам.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет, нельзя.** SVN — централизованная система: единственный источник
истины — центральный сервер. Коммит в SVN — это атомарная операция
на сервере, которая сразу становится видна всем. Без сети коммит
физически невозможен.

В Git коммит создаётся **локально** в вашем репозитории и становится
доступен другим только после `git push`. Поэтому в Git можно работать
офлайн: делать коммиты, создавать ветки, смотреть историю.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты** — если кодовая база 10+ лет живёт на SVN,
  миграция может быть дороже, чем поддержка. Особенно в госсекторе
  и банках, где процессы сертифицированы и менять инструменты сложно.

- **Хранение больших бинарных файлов** — SVN исторически лучше
  работал с бинарниками (хотя сейчас есть Git LFS). Для проектов
  с огромными ассетами (видео, CAD-файлы) SVN может быть проще.

- **Жёсткий централизованный контроль** — когда нужно, чтобы
  у разработчиков не было полной копии истории (например, по
  требованиям безопасности), централизованная модель SVN даёт
  больше контроля.

- **Простые линейные проекты** — если нет ветвления и командной
  работы, SVN проще в освоении для новичков.
